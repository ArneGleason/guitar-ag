# AGENTS.md

## Project Summary

This project is a physical-model electric guitar virtual instrument.

The goal is to build a VST3 plugin that synthesizes guitar-like sound using physical modeling, with MPE support so individual notes can bend and respond independently.

This is not a sample-based guitar instrument.

## Current Product Goal

Build an MVP that proves the core concept:

- VST3 plugin loads in a DAW.
- Multiple notes can play at once.
- Each note is generated by an independent modeled string voice.
- MPE per-note pitch bend affects only the intended note.
- Per-note pressure and/or CC74 can modulate the intended voice.
- The output is a clean DI-style electric guitar tone suitable for external amp sims.

## Important Terminology

Use **MPE**, not MPC.

MPE means MIDI Polyphonic Expression. It is required for independent per-note pitch bend and expression.

## Development Approach

Work in small, verifiable steps.

Prefer small milestones over large rewrites. After each milestone, the project should still build and the current behavior should be manually testable.

Do not introduce large architecture changes unless the current task explicitly calls for it.

Do not race ahead into unrelated features.

## MVP Implementation Order

1. Create a minimal VST3 plugin shell.
2. Implement one physical string voice.
3. Add polyphonic voice handling.
4. Add normal MIDI note on/off behavior.
5. Add MPE channel-to-voice tracking.
6. Add independent per-note pitch bend.
7. Add pressure and CC74 expression mapping.
8. Add simple pickup/tone shaping.
9. Add basic UI controls.
10. Add preset/state save and recall.

## DSP Direction

Start with a simple Karplus-Strong or digital waveguide-style string model.

The first goal is musical playability and expressive MPE behavior, not perfect scientific guitar realism.

Avoid sample playback.

Avoid building a full amp/cab/effects suite in the MVP.

## MPE Requirements

In MPE mode:

- Each active note should be tied to its own voice.
- Per-note pitch bend must affect only that voice.
- Per-note pressure should affect only that voice.
- Per-note CC74/timbre should affect only that voice.
- Bend range should be configurable.
- Normal MIDI fallback mode should still be playable.

## Code Quality Rules

- Keep audio/DSP code separate from UI code.
- Keep MIDI/MPE parsing separate from the string model.
- Avoid memory allocation on the audio thread.
- Avoid blocking calls on the audio thread.
- Avoid UI operations on the audio thread.
- Smooth parameter changes to avoid clicks.
- Prefer clear, testable code over clever abstractions.
- Keep the first implementation simple enough to debug.
